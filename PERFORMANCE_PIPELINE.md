# RF/ISAC pipeline performance changes

The normal startup and UI workflow are unchanged:

```bash
uvicorn agentic_rf_planner.api.rest:app --reload
```

## Execution stages

A plan now exposes distinct, timed stages:

1. `physical_world` — build the TX-centered OSM/mesh/terrain propagation samples.
2. `forward_coverage` — finish the active waveform's one-way products.
   - NR: RSRP, serving sector, interference, SINR and carrier power.
   - Broadcast: received carrier power, field strength and carrier-to-noise.
3. `return_environment` — only when channel analysis is enabled, build the reciprocal receiver environment.
4. `channel_analysis` — evaluate bistatic geometry, return power, Doppler and detectability at every candidate target point.
5. `heatmap` — rasterize and encode all requested coverage and ISAC layers.
6. `channel_product_export` — write the machine-readable NPZ product when enabled.

The forward coverage grid is completed before channel analysis. The large TX-centered internal cell collection is released before the receiver-centered return environment is created, so the two world-cell collections are not resident at the same time.

## Memory changes

- Internal `WorldCell` values are slotted dataclasses rather than Pydantic models.
- Broadcast planning uses the smaller `BroadcastWorldCell`, which omits cellular-sector and per-building metadata.
- `AttenuationGrid` keeps large numeric layers as NumPy arrays until JSON serialization is actually required.
- Compact API responses exclude large layers before list conversion.
- Channel/ISAC booleans and classifications use compact `bool` and `uint8` arrays.
- The forward world is cleared before the return-path world is constructed.
- One `EllipseRasterizer` is shared across every heatmap layer.

## Timing changes

- Broadcast forward products are written into preallocated arrays.
- Bistatic geometry, Doppler, echo power, SNR and detectability are evaluated in vectorized NumPy batches.
- Receiver-environment lookups support batched sampling.
- Heatmap projection, point-to-pixel mapping, support masks and feathering are prepared once per plan.
- NPZ compression defaults to zlib level 1 to reduce export latency. Set `RF_CHANNEL_PRODUCT_COMPRESSION_LEVEL=0` for uncompressed ZIP members or `1`–`9` for another compression level.

## Runtime metrics

Every plan response now contains `pipeline_metrics`:

```json
{
  "pipeline_metrics": {
    "stage_seconds": {
      "physical_world": 0.0,
      "forward_coverage": 0.0,
      "return_environment": 0.0,
      "channel_analysis": 0.0,
      "heatmap": 0.0,
      "channel_product_export": 0.0,
      "total_to_response": 0.0
    },
    "memory_rss_mb": {
      "start": 0.0,
      "after_physical_world": 0.0,
      "after_forward_world_release": 0.0,
      "after_return_environment": 0.0,
      "after_channel_analysis": 0.0,
      "after_heatmaps": 0.0
    },
    "candidate_world_cells": 0,
    "forward_world_cells_released_before_return_path": 0,
    "output_points": 0,
    "compact_response": false,
    "heatmap_size_px": 0,
    "world_cell_representation": "slotted_dataclass",
    "broadcast_cell_representation": "minimal_slotted_dataclass",
    "numeric_grid_representation": "numpy_arrays",

  }
}
```

These measurements are generated by the same Uvicorn request that runs the plan, so they show the timing and resident-memory snapshots for the selected site, radius, OSM/terrain cache state and analysis settings.

## Controlled microbenchmarks

The following separate-process benchmarks compare the previous package with this implementation on the same machine. They are not substitutes for a full 20 km site run.

| Workload | Previous | Optimized | Observed change |
|---|---:|---:|---:|
| Create 200,000 broadcast world samples | 2.281 s, 587.34 MB max RSS | 0.147 s, 146.91 MB max RSS | 15.5× faster; 75.0% lower max RSS |
| Analyze 100,000 bistatic target points | 0.816 s, 216.31 MB max RSS | 0.052 s, 174.80 MB max RSS | 15.8× faster; 19.2% lower max RSS |
| Render 15 heatmap layers, 57,600 points, 768 px | 11.917 s, 267.11 MB max RSS | 11.838 s, 245.08 MB max RSS | similar PNG-dominated time; 8.2% lower max RSS |

Use `pipeline_metrics` from a real 20 km run to identify whether the remaining dominant cost is OSM acquisition, terrain sampling, return-environment construction, propagation, PNG encoding or product export.
